## ✒️ AI 智能取名

一个取名工具，但不是"随机生成一百个名字"那种。核心流程是 **生成 → 筛选 → 解释 → 比较**，
重点在中间两步：首屏只给 8~12 个，每一个都能说清楚凭什么是它。

打开即用，**不联网也能跑**——字库、典籍库、评分引擎全都在本地。

### 它想解决的问题

普通家长取名时真正卡住的地方：名字太普通、太生僻、寓意好但不好听、字好看但组合奇怪、
谐音尴尬、重名率高、和姓搭不上、为了凑五行把名字搞难听、AI 一次给一百个却没筛过、
以及最要命的——**不知道为什么这个名字值得选**。

### 怎么用

1. **基础信息**：姓氏、性别、给谁取名、字数，再用大白话写一句你想要什么。四项就能生成。
2. **结果页**：先把"我理解到的需求"回显给你确认——听错了改一下，比翻一百个名字快得多。
3. **详情页**：寓意、逐字、出处、音律、字形、六维分析、风险提示、综合评价。
4. **收藏与对比**：收藏能记备注（"妈妈喜欢这个""和小名不搭"），最多 4 个并排比。

高级设置全部可选：喜欢/想避开的风格、指定用字、禁用字、辈分字及其位置、气质关键词、
家庭期望、出生信息、是否参考典籍与五行。

### 六个维度

音律、字义、字形、风格、易用性、独特性。

界面上只展示**档位**（优/良/一般/需注意）和**具体依据**，不展示分数。
这是刻意的：分数会让人只看分数，而这些名字之间的差别根本不是一个数字能表达的。
评分在产品内部只有一个用途——把候选排个序。

### 三条不肯让步的底线

这个产品最容易出的错不是崩溃，是**悄悄地说假话**。所以：

- **出处只标真实原句。** 每个"有出处"的名字，它的每一个字都必须出现在所引的那一句原文里，
  这条由 `npm test` 里的断言强制校验。查不到出处的一律写成"现代组合名"，绝不编来历。
- **不编重名数据。** 任何产品都拿不到公安户籍数据。这里只给"常见度：低/中/高"，
  并标明是基于近年用字趋势的估计。凡是告诉你"全国仅 3 人同名"的，那个数字是编的。
- **不把命理当科学。** 五行八字是传统文化中的命名参考方法，不是经过现代科学验证的因果预测。
  它在排序里只占很小的权重，**绝不会为了补某个五行，把一个难听难写的名字排到前面**。

### 内置数据

| | 数量 | 说明 |
|---|---|---|
| 取名用字 | 283 | 读音、笔画、结构、字义、词性、语义类别、传统五行、常见度 |
| 名字搭配 | 577 | 人工筛过的成话组合，是生成的主料 |
| 典籍出处 | 55 | 诗经、楚辞、唐诗、宋词、古文，其中 25 条能直接出名字 |
| 姓氏读音 | 158 | 含 18 个复姓，以及吴/史/杜/范这类谐音需要当心的姓 |

### 为什么要有一份"名字搭配库"

纯靠字库两两组合，永远会长出一条"看着像名字、念出来不是话"的尾巴——荷野、茗泓、诚夏。
这是语义问题不是语法问题，加再多规则也只能压住一部分。所以生成的主料是这份人工筛过的
搭配库，自由组合降级成兜底（辈分字把一个位置占死时才用）。

搭配库还顺带解决了另一个问题：**位置偏好**。有些字天生站前面（碧云、翠竹），有些天生
站后面（佳木、秋白）。这个规律不是手写的，是直接从搭配库统计出来的——往库里加词，
规则自动跟着更新。

### 接入真实 AI 模型

默认用本地引擎。想接模型的话，分工是这样的：

| 环节 | 谁做 |
|---|---|
| 候选生成 | 模型（可选）+ 本地 |
| 硬过滤 / 六维评分 / 出处标注 / 常见度判断 | **只有本地** |

模型返回的名字会和本地候选**走同一条流水线**，不开后门——模型编不出假出处，因为那个
字段根本不由它填；也漏不掉禁用字，因为过滤是本地做的。网关挂了自动降级回本地，
并在结果页如实写明。

⚠️ **API Key 不要填进任何前端页面**（包括这个应用的设置页）。正确做法是自己起一个薄网关，
Key 只存在网关那边，设置页里填的是**网关地址**。契约和一个 Cloudflare Workers 示例见
[`src/naming/ai/README.md`](src/naming/ai/README.md)。

## 🃏 斗地主 · 单人对战

一个人 + 两个 AI 的完整斗地主：洗牌 → 发牌 → 叫地主 → 抢底牌 → 出牌 → 结算，一局都不少。
不是界面 Demo，规则引擎和 AI 是分开的两层，UI 一行规则判断都不写。

### 三层解耦

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 规则引擎 | `cards.ts` `patterns.ts` `game.ts` | 牌、牌型识别、牌型比较、牌局状态机、倍数与结算 |
| AI | `ai/` | 牌面分析 → 候选生成 → 合法性过滤 → 局面评价 → 策略选择 |
| 界面 | `index.ts` `view.ts` | 只把 GameState 画出来，把点击翻译成引擎调用 |

界面拿不到规则判断能力，AI 拿不到别人的手牌——这两条都是**类型层面**保证的，不靠自觉。

### 牌型

单牌、对子、三张、三带一、三带二、单顺（≥5）、双顺（≥3 对）、三顺、飞机带单、
飞机带对、四带二、四带两对、炸弹、王炸。

边界情况逐条测过：2 和大小王不能进顺子/连对/飞机；飞机的三张必须连续；
翅膀不许拆炸弹，也不许把王炸当两张单牌带走；`33334444` 按主流判法读成飞机带两单，
不算四带两对。

比较规则：同牌型同长度比核心点数 → 炸弹压普通牌型 → 大炸弹压小炸弹 → 王炸最大。
不同的普通牌型互不相压，哪怕张数一样。

### 出错时说人话

选了牌出不了，不会只说"出牌失败"，而是告诉你差在哪：

> 顺子至少要 5 张，现在只有 4 张
> 2 不能用来接顺子（2 和大小王不参与连牌）
> 上家的顺子是 5 张，你出的是 6 张，张数要一样
> 上家是炸弹（K），只能用更大的炸弹或王炸压

### AI 怎么想的

核心指标是**最少手数**：把手牌拆成合法牌型，最少要出几次才能走完。
斗地主本质是抢手数，17 张能拆成 6 手的人，多半打得过拆成 9 手的。
每个候选出牌都按"出完这手之后还剩几手"打分，再叠上用掉多大的牌、
留没留住控制牌、对手还剩几张。

拆牌是组合爆炸问题，所以用「枚举连牌 + 记忆化 + 节点预算」：**任何手牌都在固定时间内算完**，
AI 不会因为想太久卡住。

三档难度的差别是**看得多远**，不是思考时间：

| 难度 | 会做什么 |
| --- | --- |
| 简单 | 只看自己这手顺不顺，不记牌，炸弹说炸就炸 |
| 普通 | 算出完这手还剩几手，留控制牌，不随便拆炸弹 |
| 困难 | 加记牌推断、队友配合（不打队友、给队友喂牌）、炸弹管理、残局不喂单牌 |

强弱是量出来的，不是标出来的。固定另外两家为普通难度、用同一批种子跑 400 局，
比座位 0 的平均得分：

```
easy    平均得分 -0.81   胜率 39.5%
normal  平均得分 -0.46   胜率 41.3%
hard    平均得分 +0.16   胜率 46.3%
```

（不能看"地主胜率"——地主是叫分叫出来的，不一定是同一个座位，三档的差异会被那个数字抹平。）

### AI 只能用公开信息

AI 的所有函数只收 `PublicView`：我自己的手牌、公开的底牌、每家出过的牌、每家剩几张。
**类型里根本没有别人的手牌**，所以"偷看真人手牌"在结构上不可能发生。
测试里把对手手牌整个换掉、公开信息保持不变，AI 的决定必须一模一样。

记牌器在这个前提下推断：哪些牌还没露面、还剩几张 2、对手还可能有几个炸弹、
手里这张牌现在是不是已经没人压得住。学习模式的「为什么」面板会把这些数字摊开给你看——
都是你自己也数得出来的信息。

### 状态一致性

每个动作之后自动自检：牌总数 54、没有重复牌、每家张数对得上（地主 20 / 农民 17）、
阶段和地主一致、出牌记录和弃牌堆对得上。发现异常**立刻抛错**，
不让一局已经坏掉的牌继续打下去——那种 bug 会在几十步之后才炸，到时候根本查不出是哪一步错的。

`GameState` 全部是纯数据，可以直接 `JSON.stringify`。存下随机种子就能一模一样地复现整局，
出牌记录带轮次/座位/具体的牌，为将来的回放和复盘留好了格式。

### 规则开关

底分、三家都不叫时（重新发牌 / 随机指定 / 流局）、最多重发几次、炸弹是否翻倍、
是否算春天反春——都是配置项，各地打法不同，写死在代码里以后改不动。

### 调试模式

开发环境（`npm run dev`）的牌桌左下角有个 `debug` 按钮，可以直接摆手牌、摆底牌、
指定地主和当前玩家，快速进到王炸/炸弹/飞机/四带二/残局这些局面。
生产构建里这段代码连按钮一起被去掉（`import.meta.env.DEV` 判断）。
调试摆出来的牌局照样跑查重复牌的校验——摆牌局也不许出现假牌。

## 🀄 四川麻将 · 血战到底

一张 3D 绿呢麻将桌：立体麻将牌（万/条/筒牌面全部程序化绘制）、三家牌背环坐、弃牌面朝上摆在桌心，摸牌/出牌/碰杠都有动画。规则为四川血战到底，和 3 个 AI 打一圈。

- **定缺**：开局按提示选一门缺（按钮上标了每门张数），胡牌时手里不能有缺门牌；有缺门牌时必须先打缺门。
- **出牌**：点一下手牌选中（浮起），再点一下打出。
- **碰 / 杠**：别人打出你需要的牌时会弹出按钮；暗杠、明杠都支持，杠了补摸（杠上花翻倍）。
- **血战到底**：胡了的家亮牌退出，其余继续打，直到三家胡牌或摸完牌墙；支持一炮多响。
- **番型**：平胡 / 对对胡 / 清一色 / 七对 / 龙七对 / 金钩钓 / 根 / 自摸 / 杠上花，倍数制计分，结算面板逐家列明。

## ♟️ 中国象棋 · AI 学棋教练

这不是一款"在线下象棋"软件，是**学棋软件**。目标只有一个：

> 让你知道"自己为什么输"，并且知道"下一步该练什么"。

围绕这个目标，产品是一个闭环：

```
下棋 → AI 观察 → 发现问题 → 复盘 → 专项训练 → 再实战
```

### 首页五个入口

| 入口 | 干什么 |
| --- | --- |
| ⚔️ 开始对弈 | 和 AI 下一盘，教练在旁边看着 |
| 🎯 今日训练 | 按你最近的问题排今天练什么 |
| 📖 棋局复盘 | 逐手看每一步的好坏和该走什么 |
| 🧩 战术训练 | 杀法 / 捉双 / 牵制 / 残局分类专项 |
| 📊 我的水平 | 五维能力、对局统计、棋风画像 |

每个入口下面挂的是**当前状态**（今天还有几道错题、上一盘错在哪），
不是功能说明——打开第一秒就该知道今天该干什么。

### 棋盘：正视 2D，和做题用同一块

对局、复盘、做题、残局**用的是同一块棋盘**：正视平面，不是 45 度斜视。

斜视有两个毛病：越靠上的格子越扁，判断"这个车照到哪一格"要在脑子里做一次
反投影；而且棋谱、棋书、所有教学材料都是平面图，学棋的人眼睛认的就是那个样子。
同一个产品里棋盘只有一种长相，读盘习惯也就只需要练一次。

盘上会标出：上一手从哪走到哪（蓝框）、选中的子和它的落点（绿点）、
被将的老将（跳动的红圈）、教练指出的惩罚着法（红箭头）。
两侧标了纵线号，照着棋谱学的时候对得上位置。

棋盘下方是吃子托盘和棋谱条——手机屏比棋盘高，那块空地与其空着，
不如放这两样下棋的人真的会看的东西。

### 选边 · 求助 · 认输 · 求和

开局可以选**执红先行 / 执黑后行 / 随机**。执黑时棋盘自动转过来，
自己那一方永远在下方，对手（红）会自己先走第一手。

对局中随时可以点 HUD 上的 🔍 **求助**：给出这个局面的最优解，
盘上直接画出前三手（绿 / 黄 / 灰），展开还能看完整梯次。
没算完时显示"目前看最好是…（已算 N 层，还在算）"，算完变成"最优是…"。
开局阶段引擎前几名往往只差十几分（那是误差），这时以**成熟定式**领衔
（"开局按定式走 炮二平五——炮镇中路"），并写明引擎怎么评它；教练不拦定式着法。

棋盘下方一排：**↶ 悔棋 · 🤝 求和 · 🏳️ 认输 · ⟳ 重开**。

- **认输**先问一句，确认后记为负、可以直接复盘。
- **求和**时对手真的会掂量局面：它占优就拒绝，并告诉你为什么
  （"他觉得自己占优，算下去约多一个马"）；开局才十来步也不和；局面对它不利就接受。
  拒绝之后要隔几步才能再提。
- 下到一半点"重开"或"退出"会先确认，免得手滑丢掉一盘棋。

除了将死，还有这些结局（都是竞赛规则里最常用、没有争议的部分）：

| 结局 | 规则 |
| --- | --- |
| 困毙 | 无子可动，判负 |
| 长将判负 | 同一局面第三次出现，而一方每一步都在将军 |
| 重复作和 | 同一局面第三次出现，双方都没有长将 |
| 自然限着 | 连续 60 回合没有吃子，作和（剩 10 回合时教练会提醒） |
| 无进攻子力 | 双方都只剩将士象，作和 |

AI 知道这些规则：占优时不会走回老局面把赢棋走和，也不会长将把自己判负。
你快要长将时，教练会提前说"再重复一次就判负，要变着"。

### 裁判：皮卡鱼（Pikafish）

教练、🔍 求助、"为什么？"、复盘评分，以及全部七档对手、残局和破解练习的对手，都由
[皮卡鱼 Pikafish](https://github.com/official-pikafish/Pikafish) 来算——目前最强的象棋引擎，
NNUE 神经网络评估，以 WASM 的形式在浏览器里跑，不需要服务器。

怎么一步步换到它的：

| 引擎 | 同样时间的深度 | 实测 |
| --- | --- | --- |
| 自带引擎（最早的教练） | 手机上 8 秒 6～9 层 | 80 个局面里 7 手明显失误、2 手大漏（其中一手直接走进杀局） |
| Fairy-Stockfish（上一版） | 两线程 3 秒 11～12 层 | 同样 80 个局面没有大漏 |
| **皮卡鱼（现在）** | **单线程 3 秒 19 层** | 每步 300 毫秒对下 8 盘，**8 : 0 全胜** Fairy-Stockfish（执红执黑都是把对方将死） |

- **算力**（设置页可选）：省电每步 5 秒、标准 15 秒、**全力（默认）——你想多久它算多久**，
  层数随时间一直往上涨（浏览器里约 2 秒 15 层、20 秒 20 层），上限 3 分钟；
  你一落子立刻停，**切到后台自动暂停**，回来接着算。
- 研究时前 5 名精确排序（只排 3 名能多一层，但"走法梯次"里就看不到"中""差"的那几手了）；
  你走的那一手不在前 5 名里时，教练单独把这一手**按时间算满**再判（不设层数上限——
  实测一手"再走五步被将死"的棋，封顶 15 层时判成和首选差不多，放开算才看出是杀）。
  而且是**在研究的那个引擎上算**：它在这个局面上已经想了几秒到几分钟，置换表里全是相关变化，
  接着往下算深度一下就上去。换一个冷引擎从头算，一手"走完对方四步杀"的棋要到第 18 层（两秒多）才看得见，
  十次里有一两次到时间还没看见、教练就放过去了，手机慢几倍更是几乎看不见；在研究引擎上算，同样三秒到七八十层，次次看见。
  另外只算一手时，引擎刚发现"这一手会被杀"、精确分还没算完就到时间的，按那条"最多值这么多"的上限算，不拿老分数判。
- 两条"车道"各一个 Worker：研究一条，其余短任务（精确算你那一手、对手走棋、复盘）一条，互不排队。
- **怎么叫停**：这个构建是单线程的，一条搜索中途收不到 stop。上一版的办法是把 Worker 整个掐掉重起——
  可每个引擎实例要开 **256MB** 内存，手机浏览器回收被掐掉的 Worker 很慢，**下到二三十手就再也起不来新的**，
  教练于是"刚开始还能算，后面就不算了"，悄悄退回只看子力的老判断。现在改成**拨引擎的表**：
  主线程和 Worker 共享一个整数（SharedArrayBuffer），置 1 时引擎下一次看表以为时间到了，
  交出算完的那一层、Worker 接着用。整盘棋只起两个引擎实例（实测 40 手：研究车道 1 个、掐掉 0 次）。
  浏览器没有跨源隔离、用不了 SharedArrayBuffer 时，研究分段算（每段 2.5 秒），段与段之间停。
- **倒下了也不装没事**：引擎起不来、崩了、卡死超时，这一个局面当场换自带引擎接着算
  （教练行写"自带引擎"）；连着起不来就认定这台设备跑不动它，弹一句说明，之后都用自带引擎，
  复盘打分剩下的手数也交给自带引擎，不会打到一半就没了。
- 传给引擎的是**整盘着法**，它知道哪些局面已经出现过（长将、重复）。
- 规则仍然只认 `rules.ts`：引擎给的每一手都要在我们的合法着法里。
- 不需要 SIMD；SharedArrayBuffer 只用来叫停（没有也能跑，见上）。真跑不了的浏览器自动退回自带引擎，
  设置页和教练行会如实写"自带引擎"。
- 引擎文件（约 4.8MB，浏览器会缓存）放在 `vendor/pikafish/`，构建时拷进 `dist/pika/`。
  来源、版本（`Pikafish dev-20240226-98b20a33`）和校验和见那里的 README。

> **许可**：Pikafish 是 **GPL-3.0**。原样使用、不做修改，许可证全文随文件发布在 `dist/pika/COPYING`，
> 设置页写明了引擎是谁、源码在哪。页面和引擎之间只通过 UCI 文本消息通信。
> 如果将来要把这个项目闭源商用，这一条需要重新评估。

### 评分：每一手、每一方、每个阶段

一盘下完，后台立刻开始逐手打分，**结算页直接显示"本局评分"**，不用点进复盘。

- **每一手的准确率（0～100）**：和引擎最好的下法比，你的胜率掉了多少（沿用 lichess 的公式）。
  用胜率而不是分差：多两个车时再亏一个兵无关痛痒，均势时亏一个兵可能就是胜负手。
- **每一手的称号**：妙手 !!（弃子而引擎认为值）、唯一着 !（其它走法都差两个兵以上）、最佳 ★、
  好棋、不错、可以、不佳 ?!、失误 ?、漏着 ??。对局中你每走一手，棋谱条上就标出来。
- **整盘准确率**：算术平均和调和平均各半——一手漏着能把分数拉下来，不会被几十手好棋摊平。
- **分阶段准确率**：开局 / 中局 / 残局各多少——分丢在哪个阶段，比一个总分有用。
- **优势曲线**：红方胜率随一手一手怎么变，走坏的那几手标红点、妙手标青点，点曲线跳到那一手。
- **跟自己比**："比你最近 5 盘的平均高 6"；"我的水平"里有最近十几盘的准确率走势。
- **深度复盘**：每手多给几倍时间重新打分，更准。
- 你自己走的那几手，直接用对局中教练更深的研究结果——省一半时间，也和教练当时的说法一致。
- 从存档里翻出来重看的棋不再重复记战绩（原来每打开一次就多记一盘）。

复盘里还能：**📋 复制棋谱**（带回合号和准确率，发给朋友或贴到别的软件）、
**♟ 从这里重下**（从任何一手之前的局面接着下，试试正确的走法；这种练习局不记战绩）。

### 计划：不只告诉你走哪，还告诉你往哪儿走

只报"最优是哪一手"，用户下一步照样不知道该干什么。现在 🔍 求助、教练拦棋、复盘每一手，
都把引擎的主变翻译成**计划**：

- **一句话的目标**：「3 步杀：中间有几步不将军，是在封住将的去路」「得子：净赚一个马（吃掉马）」
  「兑子：用马换对方的马，简化成车兵对士象全（书上例胜）」「弃子抢攻」「出子、占中：先把子力放到好位置」；
- **接下来几步**：你、对方、你……每一步标出在干什么（将军、吃车、捉子、过河、帅助攻、补士象）；
- **走完之后局面怎样**：「你占优（约多一个马炮）」。
- **对方的想法**：让对方"白走一步"问引擎他最想走什么——「对方想走 车7进3，直接吃你的马」
  「对方在做杀：不管的话 3 步将死你」。威胁按他那一串**实际吃到了什么**算，
  不拿分数差算（分数差里混着"你对他的威胁"：他白走一步正好逃掉你要吃的子，那是你的机会，不是他的威胁）。
  威胁大（三步以内的杀、一个马炮以上）时，教练行会提前说。

计划里的每一步都在 `rules.ts` 下验证过合法，吃子、将军、过河这些标签由规则算出来，不是模型编的。

### 做题：一手一手走到底

原来做题只判第一手——找到第一步就算对，后面怎么杀、子怎么赢到手都不管。现在：

- **杀法题要走到将死**，战术题要把整条主变走完（子真的赢到手）。每走对一步，对方自动应一手，
  顶上写着「第 2 / 3 步 · 走到将死」。
- **走出原谱之外的着法不直接判错**：让皮卡鱼核对——杀法题要求这一手之后还能在剩下的步数里杀死，
  其它题要求和引擎首选差不到 0.8 个兵；一样好就算对，接着下，对方改由皮卡鱼来应。
- **中间哪一步错了，这题算错**：说清楚是第几步、这一步该走什么、之后怎么走，并演出对方怎么惩罚你。
  可以「从头再走一遍」，这一遍不计分（第一次的结果作数）。
- **残局题**主变走完还没完：接着和皮卡鱼下到底——进攻方下到将死，守方守成和棋，达成了才算做对；
  用了提示、悔了棋的不算"自己做出来的"。测评和限时计算要控制时长，残局不接着下，但主变照样一步步走完。
- 限时计算改成**每一步**限时。「N 步杀」的标注改成按你自己走的步数算（原来按双方总手数算，两步杀写成了三步杀）。

### 残局

- **认得出是什么残局**：进入残局时教练说一次「进入残局：车对士象全（你是进攻方）。书上：单车例和士象全」，
  🔍 里有完整的残局卡片：书上的结论、引擎对这个局面的判断、要领（进攻方讲怎么赢，守方讲怎么守）。
  书上和"子力多少"不一致时一定说破——「多子不等于能赢」「书上是对方能赢的残局：尽量拖」。
- 书上的结论只收最常见、没有争议的（单车例和士象全、车兵例胜士象全、单马例和双士……），
  拿不准的组合一律不写；残局库里引擎实战验证过的局面也会对上号。单元测试逐条核对两者不冲突——
  这一核就查出库里一条写反了的（「士象全例和车炮」，书上是车炮例胜士象全），已改正。
- **实用残局（下到底）重做**，入口在 战术训练 → 专项练习 → 🏁 实用残局 · 下到底：
  - 教练一直在算，按这一局的目标说局面：「胜势：已经算到 5 步杀」「和势：照这样下去赢不了」「守得住」；
  - 每一手都有反馈，**看结果变没变**：把赢棋走成和棋、一步让对方有杀，当场说，可以悔棋重走、看正确下法和计划；
    还是赢棋只是多绕了几步，说"走软了：原来 3 步杀，现在要 8 步"；
  - 🔍 提示给最好的一手和完整计划；
  - 对手一律是皮卡鱼全力：你进攻它守得最顽强，你防守它攻得最狠。残局库的胜和本来就是皮卡鱼两边下到底判的，
    对手和判定是同一把尺子；皮卡鱼在这台设备上起不来才用自带引擎顶上，并且当场说出来；
  - 结束有小结：几手和引擎首选一样、准确率、哪几手让结果变了、用了几次提示；
  - 结果**下完当场记**。原来要点「再来一次」才记，点「下一个」这一局就白下了；
    计分只看第一次，而且靠提示、悔棋下出来的不加分。
- 复盘里残局阶段的每一手也标出是什么残局、书上怎么说。
- **残局库 343 个局面、54 类，每一个都让皮卡鱼判过胜和**（`tools/gen-endgames.ts`）：
  兵卒残局补得最多——单兵/双兵对单士、双士、单象、双象、士象全，马兵、炮兵、车兵对各种守法；
  随机摆子只是起点，每个局面引擎先搜、再两边用引擎下到底，判定和实战结果对不上的一律丢掉。
  同时标好**你是哪一方**：
  - **进攻方**的题才让你先猜「能赢 / 只能和」，猜完再下；
  - **守方**（对方多子）不再问「能不能赢」——你本来就赢不了，卡片直接写「守和练习：目标是守住」，
    进去就是练怎么守。
- **不再硬凑 60 回合**：引擎连续三次看到"已经是死和"（专业引擎算到 14 层以上），直接判和并说明为什么；
  界面上一直有操作条：🔄 重来这一局 · 🤝 提和（引擎确认是和棋才同意）· 🏳 认输，不会再找不到出口。
  回合计数写成「60 回合不吃子判和（还剩 N）」，知道还要走多久。
- **残局做题 224 道**：从残局库里挑出"只有一手对"的局面出题（`tools/gen-endgame-puzzles.ts`，
  皮卡鱼 MultiPV 3 比出第一和第二的差距），进攻方问「只有这一手能把优势保住」「找出杀棋」，
  守方问「这盘守得和，但只有这一手守得住」。主变走完接着和皮卡鱼下到底（见上面"做题"）。

### 邪门布局破解

业余对局里最常碰到的不是正经定式，而是江湖套路：开局就炮打中卒、炮打底马、急冲中兵、炮过河骚扰……
它们本身都是**亏的**，专门赌你应错——被将军就慌着垫仕、看见子就吃、被骚扰就退马。

- **套路库**（`tricks.ts`）：16 条，红黑两边都有（对方执红你破、对方执黑你破），分入门 / 初级 / 中级。
  每一条写清：它在赌什么、上当会怎样（最常见的错误应法和后果）、怎么破（每一手在干什么）、要记住的道理。
- **江湖上有名号的**：敢死炮（红、黑两边）、铁滑车（开局车一进一 / 中炮后车九进一）、双铁滑车、叠炮、瞎眼狗。
  同一个名号各地走法不一，这里各收一种走法，每条都经引擎复核。引擎的结论有一处和常见说法不一样，照引擎写：
  - **敢死炮、铁滑车送的子都该吃**（不吃反而亏）。真正的坑在第二步：他出车来捉你多吃的子，
    你舍不得、往回救，才被捉死。这种套路标"两关"（`trapAfter`），第二关单独讲、单独练：
    敢死炮吃炮之后回窝心马（马3退5）；中炮铁滑车吃马之后被退车捉，打仕弃还（炮2平4），往回退（炮2退1）亏约 4 个兵。
  - 对局里第二关也认得出：教练在那一步提醒「别恋子」，陪练吃了子之后照套路出车来捉，复盘标出第二关是过了还是上当。
- **🏁 破解到底**：破解那几手不算完。破解摆好之后和皮卡鱼接着下——它执走邪门的一方、全力抵抗——
  下到**将死**，或者引擎连续三步确认**胜势已定**（约多一个大子），才算「完全破解」；
  到了胜势可以就此收工，也可以选「接着下到将死」练收官。靠提示、悔棋下出来的不记「完全破解」。
  - 十大邪门布局里其余几种这次没收：御驾亲征、九尾龟本身亏，但引擎找不出让你顺手吃大亏的陷阱
    （九尾龟最多是跟着冲边卒丢一个卒）；鸳鸯炮、龟背炮、雷公炮、沉宫马查不到确切走法，不凭记忆编。
- **引擎说了算，不是凭记忆写的**：`npm run check:tricks` 让皮卡鱼逐条复核——邪门着本身确实亏（≥60）、
  破解那一手和引擎首选差不到 150、上当那一手比破解差 150 以上、破解之后比对方走邪门着之前处境好，
  写在数据里的数和复核结果对得上。素材也是引擎找出来的（`tools/find-tricks.ts`：量一手棋亏多少、
  哪些"顺手"的应法会上当）。
- **学棋里**：战术训练 → 专项练习 → 🗡 邪门布局破解（布局体系页也有入口）。每一条可以
  📖 看套路和破解、⚠️ 看上当会怎样、🎯 你来破解（套路摆好，你先走再对答案，全对记为"已破"）、
  ⚔️ 从这里实战（从套路走完的局面和对手下一盘练习局）。
- **对局里**：设置页"对手开局"选 **邪门布局**，对手就专走这些套路（你走出套路之外它照常下）。
  对方一走邪门着，教练当场点破：「对方走的是邪门布局「黑方炮打中兵将军」：……破解：马三进五——马直接把将军的炮吃掉」。
  破解着法算定式：教练不拦，🔍 求助以它领衔。复盘里标出对方的邪门着，以及你是"破解成功"还是"上当了"。

### 布局体系：按谱路走够十几个回合

原来每套布局只有 6～10 手，邪门布局的破解只有三五手——走两三步就完，学不到东西。现在：

- **20 套布局，按体系分组**：屏风马（对过河车平炮兑车、破急进中兵、破牛头滚、对五七炮、对巡河炮、进三兵、巡河车）、
  三步虎、左炮封车、单提马、反宫马、顺炮、列炮、过宫炮、士角炮、飞相局（含对左中炮）、仙人指路（含对兵局）、起马局。
  每套写清楚核心思路、对方怎么破、容易踩的坑。
- **"破法"课**：牛头滚、三步虎这类江湖常见、但次序有毛病的走法，谱上照走它的特征着，
  后面皮卡鱼演示怎么惩罚。三步虎的结论和常见说法不一样，照引擎写：马8进7、车9平8、炮8平9 这个次序，
  红方车二进九兑车、马7退8 吃回之后中卒没人保护，炮五进四白吃中卒，黑方亏 4～5 个兵；
  变化里给出稳一点的次序（先马2进3 保住中卒）。五六炮我写不出皮卡鱼认可的谱序，没收。
- **主线每套 15～17 回合**：前面几个回合按定式谱写（`openingspecs.ts`，人写的着法和说明），
  之后由皮卡鱼每手深算 2.5 秒延伸下去，**每一手配一句"这一手在干什么"**（`movenote.ts`：哪个子出动、
  过没过河、吃了什么、是兑子还是白吃、捉了谁、将没将军——只说看得出来的事，不猜意图）。
  谱不停在兑子半路：最后一手是吃子或将军就接着走到局面平稳，收尾那句「走到这里：红方略好」才对得上盘面。
- **45 个变化**：主线上"第二好的一手和最好的差不到 0.25 个兵"的地方，自动补成变化，也往后走十几手；
  人写的变化（过宫炮对进马、飞相局对过宫炮、仙人指路对卒底炮……）照样核对、延伸。
- **谱上的每一手都让皮卡鱼核对过**（`tools/build-openings.ts`）：人写的着法比引擎首选差 1.5 个兵以上就报错停下——
  这一核就查出我写的四处错谱（过宫炮第四手、士角炮的次序、五七炮里黑方的一手、反宫马的出车），都改了。
  江湖攻法本身的特征着（比如牛头滚的冲中兵）引擎不认可但要保留的，标出来、讲解里写明"引擎：这一手比 X 差约 N 个兵"。
- **怎么练**：📖 看主线（每一手都讲）→ 🎯 执红 / 执黑自己走一遍。走了谱外的着法不直接判错，
  皮卡鱼核对是不是一样好（差 0.6 个兵以内算对），然后接着原谱走。走过的布局卡片上标着最好成绩。
- **⚔️ 从这里接着下**：谱走完了，中局才开始。谱的最后一手走完（或者在详情页直接点），从这个局面和对手接着下，
  对手档位按你的实战分推荐——把布局的思路用到实战里，而不是背完谱就算了。

### 邪门布局：破解走到十几个回合

人写的破解只有三五手。用户原话："破解往往不是三四步的事，可能需要十几步甚至更深入的思考"。
现在每一条破解都接着由皮卡鱼两边按最好的走下去，**破解谱至少 10 个回合**（`tools/deepen-tricks.ts`），
上当那条也延伸到对方把便宜兑现。每一手配说明、记引擎分。🎯 你来破解要一直走到谱的最后一手，
中途走了谱外的着法同样交给皮卡鱼判。

### 中局组合：要连走好几步的得子和杀棋

原来的战术题多是一两步就完。中局组合（`tools/gen-combos.ts`）：

- **从对局里找**：两个中等档位的皮卡鱼对下（它们会犯人会犯的错，留下真实的战术机会），每一手快速看一眼——
  最好的一手比第二好的强出 2.5 个兵以上 → 深算复核，主变里找到"便宜真正拿到手"的那一步
  （子力净得 2.5 个兵以上、自己没有子挂着，或者将死），之前要走几步就是这道题的步数。
- **102 道，按步数分档**（2–3 步 41 / 4–5 步 30 / 6–7 步 31）**、按主题分卡**：连将杀、杀（中间有安静着）、
  弃子、抽将、捉双、将军抽子。每一步都判，走到便宜拿到手才算对；走了谱外的着法皮卡鱼核对。
- 难度用和其它题一样的尺子，再按步数保底：要连走五六步的组合，第一手再显眼也不是入门题。

### 残局阶梯：5 步杀 → 10 步杀 → 15 步杀 → 20 步杀

原来的杀法题多是两三步。残局阶梯（`tools/gen-mate-ladder.ts`）：

- **从终点往回切**：残局库里的胜局让皮卡鱼两边下到将死，从将死那一步往回数，在剩 5、10、15、20 步的地方切出局面，
  每一个切点再让皮卡鱼复核 8 秒，确认最快几步杀。同一个残局，最后几步怎么收在低档，再往前推在高档——
  **从终点往回学，前面每一步都知道是为了走到哪个杀法**。
- 残局库里多数胜局离将死只有几步，长线的太少，另外随机摆了车对单缺士、车马对单车、马炮对士象全、
  炮兵对士象全、三兵对士象全这些长线残局（`tools/gen-long-mates.ts`），只留 12～30 步杀的局面切进高档。
- **296 题**（5 步档 131、10 步档 105、15 步档 56、20 步档 4），同一档里按兵类、马类、炮类、车类、组合分组。
- **每道题的"最快几步"都对得上**：示范解法正好是复核的最快步数才收。步数对不上的（8 秒复核说 57 步杀、
  示范 21 步就杀死了）再用 30 秒复核、每手 5 秒重下一遍，还对不上就删——前一版里这样的题 30 道，删了 21 道。
- **20 步档题少，是因为真的难找**（现在 4 道：20、20、20、24 步杀）：随机摆子时引擎说"22 步杀"的局面，
  多算一会儿大多缩到十五六步。后来换了找法——专找"算不出杀、但分数已经很高"的长线胜局（双马、马兵、炮兵对士象全），
  下到将死后在剩 18～26 步之间挨个切，哪个切点复核对得上收哪个。
- **📖 看示范解法**：下完一道（赢了输了都行）可以回看皮卡鱼的示范杀法，从题目局面一手一手讲到将死，每一手配说明。
  先自己下、再对答案——不下就看，学不到"原来应该这样收"。
- 每题和皮卡鱼下到将死（它用最顽强的守法）。最快步数杀死 ★★★，多走几步 ★★，绕得远 ★；靠提示、悔棋只给一颗星。
  **上一档过一半才解锁下一档**，阶梯要一级一级上。

### 每日训练

一三五（阶段 2 起）轮中局组合 5 题；周四（阶段 3 起）布局体系过一套；阶段 3 起偶数日的残局块换成残局阶梯"往上爬一题"
（已解锁的最高一档里还没杀过的第一题）。

### 没下完的棋

每走一步自动存一份。手机浏览器切到后台一会儿就可能回收页面，刷新、手滑关掉也一样——
回到象棋首页会看到"⏯ 有一盘没下完"，点继续就回到原来的局面，悔棋、长将判定照常可用。
下完、认输、议和，或者明确选了"退出，放弃这一局"，才会删掉。

### 一个局面只有一个裁判

教练判你这一手、🔍 求助给最优解、对手掂量要不要和棋，读的都是**同一份分析**：
轮到你走时，引擎就在后台（单独一条线程，不拖慢对手）把这个局面一层一层往深算，
你想棋的时间就是它的算力。

之前教练用 0.9 秒的浅层分析（4 层），求助用 6.5 秒的深层分析——
快被将死时，教练拦着不让出帅说"会丢子"，一按求助最优解恰恰是出帅。
现在：

- 教练至少看到一定深度才判（专业引擎 10 层、自带引擎 4 层；秒落子时等它一小会儿，通常不到半秒）；
- 判得早、之后算深了结论变了，提示条会**当场改口**（"改判：这一手没问题，放心走"）；
- 求助推荐的那一手，教练在任何档位都不会拦；
- 报警的话全部取自引擎的主变（"走完之后对方会 车5进1，吃掉你的车"、
  "对方有 2 步杀，从 车5进1 开始"），不再用静态兑子的套话；
- 差得太多的棋，分析里只证明"至少差一个车"，教练要拦它时再单独精确算一次，
  把真实后果说出来——和复盘说的是同一句话。

### 教练模式：只提醒，不代劳

你准备走一步明显有问题的棋时，教练会开口，但**绝不替你走，也不拦着你**。
按钮只有"换一手"和"就这么走"——坚持走错也照走，那一手会被复盘抓下来单独讲，
结算页和复盘列表里标 🧑‍🏫，写明教练当时说了什么。

四档提示，对局中随时切换（HUD 上的 🧑‍🏫 按钮）：

| 档位 | 说到什么程度 |
| --- | --- |
| 关闭 | 安静对弈 |
| 轻提示 | 只说一句"这里似乎有更好的选择"，怎么回事自己想 |
| 标准提示 | 说清楚会发生什么；对方新捉了你的子、摆好了一步杀时提前说（默认） |
| 教学提示 | 在标准之上，每一步读出对方的意图；可以点"为什么？"追问 |

棋盘下方有一行教练状态：平时显示"教练在看 · 已算 N 层"，有话说的时候换成那句话。
除了拦坏棋，教练还会：

- **提醒对方的威胁**：轮到你时对方已经摆好一步杀，先说出来（这是新手最常见的输法）；
- **读对方上一步**："对方 炮二进四：在捉你的车"；
- **夸真正的好棋**："只此一手"、"解杀了"——只会挑错的教练让人越下越怕；
- **局面没救时说一次实话**：对方已经有 N 步杀，最顽强的是哪一手，给出悔棋/认输/接着下三个出口，
  之后不再逐手唠叨；对手是会看走眼的低档时，改说"它不一定看得见，接着下还有机会"；
- **解释点不动的原因**：被牵制的子、解不了将的子、将帅照面，点了会说为什么不能走。

点开"为什么？"给的不是一句话，是一份从全局出发的解读：

```
这一步在做什么      车五进二：过河。
局面即时的变化      ✅ 空间：你过河的大子价值从 0 涨到 1000…
                    ·  机动性：对方只剩 8 手可走，但那是被将军逼的，
                       他解完将就恢复了，别当成真的把他困住
问题在哪            你的车没有保护，对方走 车5进3 就吃掉，净亏约一个车
对方接下来打算      车5进3　帅五平四　车5平6
更好的选择          1. 车五进五 —— 将军、吃子、逃子、过河  ← 引擎首选
                       后续：车五进五　将5平6　车五平三
                    2. …（每一手都说清它想干什么、比首选差多少）
你这手的想法        （想法本身不一定错，问题多半出在时机和代价上）
                    · 过河：把子力推进到对方半场，抢空间
这个阶段的通用道理  （不是针对这一手，是这个阶段都适用）
```

**每一个数字都是算出来的**：意图、空间、机动性、士象、九宫压力由规则算，
候选走法和后续变化由搜索引擎给，通用棋理单独成段并标明"不是针对这一手"——
不标出来，用户会把它当成针对性点评，下次遇到不适用的局面还照着做。

### 复盘：看见惩罚，而不是看见分数

下完一盘，引擎逐手打分，标出 好棋 / 不错 / 可以 / 不佳 / 失误 / 漏着。
点任意一手，棋盘回到那个局面，直接把**对方的惩罚手段**摆出来：

> 走完这步，对方 车八进五 就吃掉你的马，改走 马三进四 更好。

整盘棋自动存档，之后随时能从"最近棋局"翻回来重看。

复盘面板在手机上占半屏、棋盘留在上半屏不被盖住；点开一手之后总评收起来，只留这一手的讲解。
翻页不用来回点：◀ 上一手 · **⚠ 下个问题手**（直接跳到下一个失误/漏着）· 下一手 ▶，
棋盘上左右滑、键盘 ← → 也能翻；📊 总览 回到整盘的分数和曲线。

### 错误画像：基于真实数据，不贴标签

系统长期记录你的失误类型（送子 / 贪吃 / 漏看威胁 / 漏将 / 漏杀 / 走软），
汇总成一段画像，例如：

> 你进攻意识强、爱换子，但对方吃你子的频率偏高。
> 最该先改的一条是**贪吃**：吃之前先算账，亏本的子宁可不吃。

**样本不够就不下结论**（少于 3 盘、或一盘都没复盘过，只会说"再下几盘"），
每条特征都必须配一个数出来的证据。

### AI 教练对话

可以直接问：「为什么我输了？」「这一步为什么错？」「我这种错误是不是经常出现？」

回答基于这一局的复盘结论和你的历史数据。问到需要重新搜索才能回答的问题
（"如果我当时走马会怎样"），它会老实说要重新算，而不是编一段听起来专业的废话。

### 棋规

完整实现并有 60 条单元测试覆盖：马蹩腿、象塞眼且不过河、士帅不出九宫、
炮隔架吃子、兵过河横走、将帅不可对脸、将军 / 应将 / 将死 / 困毙。

### 水平评估：以实战为准

以前的评估会把一个下不赢"大师"档的人评成"专业级"。查下来是四处一起出的问题，全部改了：

| 哪里出的问题 | 以前 | 现在 |
| --- | --- | --- |
| 测评一步跳多少 | 每题固定 ±400，没有上下限，做对几道就冲出题库难度 | 步长 220 → 45 递减，估分封在这一维题库的难度区间附近 |
| 什么题算分 | 同一道题做第二遍、第三遍照样加分；比你低很多的题做对也加分 | 只有第一次做算数；比你低 250 以上的题做对不加分 |
| 分数怎么对应段位 | 一千五六就叫"专业级以上" | 按天天象棋的段位重新对照（`TT_LEVELS`），一千五六是业余中上 |
| 实战算不算 | 完全不算——题做得再好、实战连输，水平照样往上涨 | **实战分**：和各档 AI 下的每一盘按 Elo 算（开着教练、用了提示的按比例少算），下够 3 盘后水平以实战为准 |

- 首页、我的水平、训练计划看的都是同一个数（`honestLevel()`），并且说清楚来源：
  「实战分 1180（8 盘）」；做题分比实战高很多时直接说破「题做得来，实战里用不出来」。
- 老存档打开时会把以前的对局补算进实战分（练习局和太短的棋不算，只补一次）。
- 开局设置页按实战分标出**推荐对手**（实战分附近那一档），下完结算页写「实战分 1150 → 1172」。
- 训练阶段要看实战：做题分全过线、但实战每盘漏着多于一次，照样停在阶段一。

### 每日计划

- 还没下够 3 盘：计划里第一件事就是下一盘，先有实战数据，后面的计划才有依据；
- 之后每天都有一盘对局，对手按实战分推荐；
- 专项题**先出没做过的**（难度在你 ±300 以内），实在做完了才轮到最久没碰过的那道，
  计划里写明这一类还剩几道新题——不会再天天做同几道。
- 题目怎么问由引擎按正解真正在干什么来定（`tools/classify-puzzles.ts`）：
  杀棋问杀棋、赢子问赢子；**你已经落后的局面，问的是「你落后约一个马炮。找出最顽强的防守」**，不会再问你怎么赢子。

### AI 难度：七档都是皮卡鱼

原来前五档是自带引擎加扰动，和顶两档（皮卡鱼）之间断了一大截——用户原话"只有最后两档有难度"。
现在七档都用皮卡鱼走棋，按档位削弱（`pikalevel.ts`）：

- **按节点数搜，不按时间搜**：同一档在旧手机和新电脑上一样强。节点少 = 算得浅 = 深一点的战术看不见，这正是人会犯的错；
- **从前几名里按分差随机挑**：分差越小越可能被挑中，亏太多的不挑，偶尔"看走眼"放宽一次。
  挑的都是引擎前几名里的着法，不会出现人绝不会走的怪棋；一步杀谁都不会放过，也不会自己走进一步杀；
- 皮卡鱼还在加载就等它，真起不来才让自带引擎替补，并如实说出来——**替补下的棋不计入实战分**。

每档多少分是**对下实测**的（`tools/calibrate-levels.ts`），不是估的：

| 档 | 皮卡鱼配置 | 分 | 怎么定的 |
| --- | --- | --- | --- |
| 入门 | 600 节点，前 8 名里随便挑 | 650 | 和初级互下 2 比 22，分差打六折推的（误差大） |
| 初级 | 1500 节点，前 7 名 | 880 | 对旧「高级」6 盘 0.5 分 |
| 中级 | 2500 节点，前 6 名 | 1050 | 对旧「高级」8 盘 1.5 分 |
| 高级 | 5000 节点，前 6 名 | 1300 | 对旧「高级」12 盘五五开（锚点） |
| 大师 | 6000 节点，前 6 名 | 1420 | 对旧「大师」10 盘 4.5 分 |
| 特级大师 | 1.2 万节点，前 5 名 | 1690 | 对旧「大师」10 盘 8 分 |
| 棋王 | 全力，每步 3 秒 | 约 2200 | 5 万节点那一档对它 8 盘只拿 1.5 分，再往上推的 |

尺子以旧版的「高级」（1300）和「大师」（1450）为锚——实战分以前就是在这两档附近算出来的，这样前后接得上。
两个要说在前面的发现：一是同一个引擎自己跟自己下，差一点就一边倒（相邻配置经常 16 比 0），
所以能对旧档下的都按对旧档的结果算，只有入门、棋王是用互下的分差打折推的，误差大；
二是旧尺子本身就不齐——旧"中级"名义上只比旧"高级"低 150，实际连新的最低档都下不过。
你的实战分跟着输赢走，几盘之后自己会落到对的位置。
老存档里补算的棋是和旧引擎下的，按旧分算。让子定级也换成皮卡鱼：让双马 / 让单马 / 分先都对「高级」，再往上对「大师」「特级大师」。

## 🎤 唱吧减压 · 学唱歌

给上班压力大的人：把压力唱出去，顺便把歌练好。需要允许**麦克风**权限（声音只在本机分析，不会上传）；拒绝麦克风时仍可用「欣赏模式」听旋律跟着哼。

### 四个玩法

0. **🎯 高音训练营** —— 专治「高音上不去、一唱就费嗓」。
   - **21 条专业练声曲**，全是声乐课上真用的那些：嘟嘴、弹舌、吸管发声、哼鸣、警笛滑音、小狗哼唧、咕音琶音、真假声翻转……每条都写清楚**怎么做**、**为什么有用**、**最容易做错哪里**，不用专业术语。
   - **30 天课程**，分四个阶段：省力发声 → 找到头声 → 打通换声 → 混声高音。每天 3~4 条，几分钟。
   - **自动模进**：像老师弹琴一样，一条音型跟一遍就升半音，一直到你唱不动为止自动停——不会让你硬顶。
   - **费嗓预警**（这个是别家没有的）：实时判断你是在唱还是在喊。检测破音、声音发抖、越唱越响、漏气，屏幕上一条状态条从绿变红，并直接告诉你「有点在喊了，同样的音高试着唱得更小声」。
   - **音域成长曲线**：每天记录你唱到的最高音，画成折线，看得见自己在涨。
   - 累了随时点「⬇ 降两个音」或「⏭ 这条够了」。练习库里带 🌱 的是半闭合练习，几乎不伤嗓，嗓子累时只做这些。

1. **🫁 减压开嗓**
   - **引导呼吸**：跟着圆圈「吸气 4 秒 → 屏住 4 秒 → 呼气 6 秒」做 5 轮，先放松再开口。
   - **音阶开嗓**：跟参考音哼 do-re-mi 五度音阶，一组比一组高半音，实时显示你的音高有没有贴住台阶。
   - **测音域**：唱出你最低和最高的舒服音，App 记住你的音域，跟唱歌曲会按它自动推荐移调。
2. **🎯 音准训练**
   - **单音模仿**：听一个音唱出来并稳住，音准表实时显示偏高/偏低多少音分，唱准拿连击翻倍得分。
   - **声控小鸟**：用声音的高低控制小鸟飞行穿过缺口——唱得高飞得高，停下会下坠。放声乱唱也是一种减压。
3. **🎤 跟唱打分**
   - 二十二首经典公版旋律，按难度排序：
     - **入门**：小星星、两只老虎、新年好、划船歌、玛丽的小羊羔、伦敦大桥、小白菜
     - **简单**：生日快乐、欢乐颂（唱名版）、小蜜蜂、铃儿响叮当、噢！苏珊娜、樱花、红河谷、多年以前
     - **进阶**：茉莉花、送别（片段）、友谊地久天长（唱名版）、平安夜、摇篮曲（片段）、绿袖子、奇异恩典
   - 每首歌卡片上标出**原调下的最高音**；测过音域后还会标「够得着 / 刚好到顶 / 高 N 个半音」，练高音时一眼知道哪首现在能唱。
   - 钢琴卷帘滚动显示音符条和歌词，唱的同时**实时画出你的音高曲线**；唱过的音符绿色=准、红色=跑调，一眼看到问题在哪句。
   - 唱完打分评星（⭐~⭐⭐⭐），每首最高分自动保存；`♭ / ♯` 按钮可 ±6 半音移调找到舒服的调。
   - 唱低八度或高八度都算对（评分按八度折叠），男女生都能直接唱。

### 技术细节

- 音高检测用 **McLeod 风格归一化自相关（NSDF）+ 抛物线插值**，纯 TypeScript 实现、零依赖，检测范围 C2~C6。
- 参考音与伴奏全部用 **Web Audio 实时合成**（八音盒音色），无任何音频文件。
- 音域、每首歌最高分、声控小鸟纪录保存在浏览器 localStorage。

## ⚔️ 手机 MOBA · 一路推塔

一局约 3～6 分钟的单路推塔对战。你操纵一名英雄，带着自动出兵的小兵沿唯一一条兵线推进，逐个拆掉对面的防御塔，最后摧毁**敌方水晶**即获胜；己方水晶被摧毁则失败。对手是一名会推线、越塔、追击和撤退的 AI 英雄。

### 操作（手机 / 电脑）

- **左手虚拟摇杆**：控制英雄走位。
- **英雄自动普攻**：进入攻击范围会自动攻击最近的敌人（优先敌方英雄）。
- **右手四个技能键**：
  - **Q 能量弹** —— 朝当前方向发射穿透弹，命中造成爆发伤害。
  - **W 震荡新星** —— 身周爆发，伤害并减速附近敌人。
  - **E 疾冲** —— 朝当前方向瞬移一段距离，用来追击或逃生。
  - **R 雷霆审判** —— 6 级解锁的大招，对目标区域造成巨额伤害。
- 技能键会显示冷却读秒；法力不足或未解锁时不可释放。

### 核心玩法

- **补刀与经济**：击杀小兵、拆塔、击杀敌方英雄可获得金币，另有少量被动收入。
- **升级**：靠近战场的击杀会给予经验，升级提升生命/攻击并解锁大招（最高 10 级）。
- **装备商店**：点右下角 🛒 打开商店，**回到己方水晶附近**即可反复购买力量水晶、生命宝石、疾速符文、疾行之靴（价格递增）。
- **防御塔机制**：塔会优先攻击小兵，孤身越塔很危险；必须先拆掉靠前的塔，才能攻击后面的塔和水晶。
- **阵亡与复活**：英雄阵亡后会在己方水晶处等待数秒复活，等级越高复活越久。
- 右上角**小地图**实时显示双方水晶、防御塔、英雄与兵线。

## 🏹 塔防远征 · 3D 塔防

下班后开一局，建塔、升级、顶住 25 波进攻，守住你的水晶基地。

1. **选地图、难度和模式** —— 两张地图（蜿蜒山谷、双路汇流），三档难度（简单 / 中等 / 困难），两种模式（标准 25 波 / 无尽模式），难度越高敌人越强、初始金币越少。
2. **建塔** —— 点地图上的灰色空格位，弹出环形菜单，选一种塔建造（会花金币）。
3. **升级 / 出售** —— 点已经建好的塔，可以升级（最高 3 级）或出售回收 60% 金币。
4. **开始波次** —— 点底部黄色按钮放出一波敌人。击杀敌人赚金币，清完一波有奖励。
5. **守住基地** —— 敌人走到终点会扣生命，生命归零就失败；顶住全部 25 波就通关。

### 操作（手机）

- **单指拖动**：平移视角
- **双指捏合**：缩放
- **点空地**：建塔
- **点塔**：升级或出售
- 右上角可 **暂停** 和切换 **x1 / x2 速度**

### 四种防御塔

| 塔 | 特点 |
|---|---|
| 🏹 箭塔 | 攻速快、单体，性价比高的基础输出 |
| 💣 炮塔 | 范围溅射，克制成群小怪（打不到飞行兵） |
| ❄️ 冰霜塔 | 命中减速，控制型，配合输出塔很强 |
| ⚡ 闪电塔 | 高伤害、攻速慢，专治重甲兵和 Boss |

五种敌人：普通兵、快速兵（快而脆）、重甲兵（血厚慢速）、飞行兵（走直线捷径，只有能对空的塔打得到）、Boss（每 5 波一个，血量极高）。

### 两种模式

- **标准 25 波**：顶住 25 波（含 Boss 波）即通关。
- **无尽模式**：波次永不结束、敌人越来越强，比谁撑得久，单独记录每张地图每个难度的最高波数。

### 更多细节

- **每波守住后随机奖励**：除固定清波金币外，还会抽一个随机奖励——金币补给 / 巨额宝箱 / 战争红利（存款利息）/ 武器强化（全塔永久增伤）/ 基地维修 / 免费升级。
- **音效**：全部用 Web Audio 实时合成（无音频文件）——建塔、开火、击杀、清波、胜负都有反馈，右上角 🔊 可随时静音。
- **打击特效**：命中溅火花、击杀迸碎片，Boss 死亡爆得更夸张。

进度（每张地图每个难度的通关状态、标准最高波数、无尽最高波数）会自动保存在浏览器里。

## 🌱 成长观察 · 孩子成长记录（独立页面）

```
https://zhaolinzhou7-ops.github.io/Life/grow/
```

给家长自己用的记录工具：只在一部手机上用，不需要账号，不联网同步，**所有数据只存在这台手机的浏览器里**。

### 装到 iPhone

1. 用 **Safari** 打开上面的网址（不要在微信里打开）。
2. 点底部的分享按钮（方框加向上箭头）→ **添加到主屏幕**。
3. 以后**只从主屏幕图标打开**。第一次从图标打开时要联网，等几秒让它把自己存进手机；之后断网也能用。

> Safari 和主屏幕图标是两个互不相通的"抽屉"：在 Safari 里记的内容，图标里看不到。删掉主屏幕图标会连数据一起删掉。

### 四个功能

- **记录**：打开就是它。日期默认今天（有"今天/昨天"快捷键），写一句话，点标签（兴趣、情绪、社交、表达需求/说"不"、新尝试、自理、身体、睡眠，可多选），需要时点"⭐ 第一次"，保存。写到一半被切走，草稿还在。
- **时间线**：按月翻看，点月份可直接跳；标签多选筛选（含任一即显示）、只看"第一次"；搜索框搜全部月份，标签名也能搜到。点一条可修改或删除。
- **健康节点**：预置体检、视力、牙科、疫苗，可以再加。两种填法：上次日期 + 间隔几个月，或者直接填下次日期（疫苗照接种本填）。30 天内到期和已过期的排最前面，记录页顶上也会提一句。
- **发育对照**：能力项据国家卫健委《儿童心理行为发育问题预警征象筛查表》整理（4–6 岁），与儿保门诊版本不一致时以门诊为准。每项只有"能做到 / 还做不到 / 不确定"；按出生日期只对照已到的年龄段，以后的年龄段灰着、不参与提醒。任何一项"还做不到"提示"建议到儿保门诊复查"；另有一问"语言或社交能力倒退"，选"有"提示尽快就医。页面顶部固定写着"筛查参考，不是诊断"。

### 设计红线

不给孩子打分、不算达成率、不排名、不和任何人或"平均水平"比较；不做打卡、连续天数、徽章、排行榜。
`tests/ui/grow.mjs` 会检查发育对照页不出现百分比、"几项中几项"、分数之类的字眼。

### 数据安全：备份是唯一的保险

- **导出**："备份"页 → 导出备份文件。iPhone 上会弹出分享面板，选"存储到文件"→ iCloud 云盘，或发给微信"文件传输助手"再存到电脑。文件是普通 JSON 文本。分享和下载都不好用时，可以"复制备份内容"粘贴保存。
- **每月提醒**：这个月还没导出过，打开时记录页顶上会提醒，直到导出或点"本月不再提醒"。
- **恢复**：一律按"合并"处理——备份里有、这里没有的补上；两边都有的留改得更晚的；已经删掉的记录不会因为恢复旧备份又冒出来（删除时留了一个只有 id 和时间的空壳，原文不保留）。
- **长期保存**：启动时向浏览器申请"这份数据很重要，别自动清"，"备份"页能看到是否开启。
- **在电脑上看**：电脑浏览器打开同一个网址 → 备份 → 选择备份文件。电脑上是独立副本，改了不会同步回手机。
- **网址不要换**：数据跟着网址（域名）走。和小游戏合集同一个域名，所以库名、键名都带 `grow` 前缀互不干扰。

- 独立的第二个页面（`grow/index.html`，Vite 多页面构建），不加载小游戏合集的 `coi-serviceworker`。

- 图标：`node tools/grow-icons.mjs` 生成 `public/grow/icon-*.png`（iPhone 主屏幕图标只认 PNG）。

## 技术说明

- **首页 / MOBA**：纯 **Canvas 2D** 俯视渲染，无任何外部图片或模型文件，完全自包含；较重的 3D 塔防按需（动态 import）加载，因此进入首页和 MOBA 时不会下载 Three.js。
- **塔防远征**：用 **Three.js** 做 3D 渲染，所有模型都是用几何体程序化生成的低多边形风格；音效用 Web Audio 实时合成。
- **Vite + TypeScript** 开发和构建，产物是纯静态文件；进度用 **localStorage** 保存。

### 象棋：棋力与教学分离

这是整个学棋模块的架构底线——**语言模型只负责解释，不负责判断**：

```
规则引擎 rules.ts ─┬─ 搜索引擎 ai.ts（Worker 线程）
                   └─ 教学事实层 teach.ts（静态兑子计算）
                              ↓
                      结构化事实（谁能吃你什么、亏多少、对方怎么惩罚）
                              ↓
                      讲解层 llm.ts ──► 校验闸门 ──► 界面
```

- 「你这个马没人保护、对方车能白吃」这类结论**全部由规则算出来**，
  不是让模型看着棋盘感觉。教学事实层用静态兑子计算（SEE），纯函数、不搜索、
  单手 1.2ms，所以教练能在你落子那一瞬间给反应，而且结论可复现、可测试。
- 交给讲解层的事实清单里**没有棋盘**——模型看不到棋盘，就编不出
  "你的车在二路"这种话。
- 讲解回来还要过一道闸：回话里出现的每一个着法记谱都要和事实清单对一遍，
  对不上整段丢掉、退回模板文案。宁可讲得干巴，也不能讲错。

### 离线 / Mock 模式

**没有任何 AI API 也能完整使用**：下棋、AI 对弈、复盘、做题、看画像全都不依赖网络。
讲解默认走本地模板（每一句都由规则算出来，一个字不会错），
这是默认方案不是降级方案。

要接真模型的话，设 `VITE_COACH_API` 指向**你自己的后端**，
前端只往那个地址发结构化事实、收一段文本，**密钥留在后端，前端碰不到**。
